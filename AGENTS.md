amplifier-app-opencode makes Amplifier Agent the agent inside opencode 2.x: a Python package that installs an opencode
plugin, and the plugin that runs Amplifier's HTTP face.

## Orientation

```
src/amplifier_app_opencode/cli.py       amplifier-opencode: install, uninstall, doctor, face
src/amplifier_app_opencode/cleanup.py   finds and removes what 0.4.x generated
src/amplifier_app_opencode/face.py      runs amplifier-agent-http's face for the plugin
src/amplifier_app_opencode/plugin_bundle/amplifier/    generated by `make plugin`; never edit by hand
plugin/src/                             the opencode plugin's server part (TypeScript, built with bun)
plugin/tui/                             the opencode plugin's TUI part, copied as source
tests/                                  unit tests for logic that is hard to get right
tests/e2e/                              Digital Twin Universe suites; its own uv project
.agents/digital-twin-universe/          the e2e profile
```

- Sources of truth, in order: amplifier-agent's `contracts/http-face.v1.md` and `docs/http/` for the face, opencode's
  plugin API at the tested version (`reference/opencode` in the workspace), then this repo's README.
- The face is the only interface to Amplifier. A feature that needs more from Amplifier is a change to the face in
  amplifier-agent first, released before this repo depends on it.
- The version matches the amplifier-agent release it is built against. Bump `version` in `pyproject.toml` and the
  `amplifier-agent-http` ref together.
- The opencode version the plugin is tested against is the one the e2e profile installs. Moving it means reading
  opencode's changelog for plugin API changes and running `make e2e`.

## Checks

```bash
make check    # ruff, ty, tsc, and the plugin bundle is up to date
make test     # pytest and bun test
make e2e      # needs Docker and OPENAI_API_KEY; SUITE=<name> runs one suite
```

- `make check` and `make test` pass before work is done. Changes to install, the plugin, or the face command also
  pass `make e2e`.
- Prove behavior with e2e suites that install and run as a user would. Add unit tests only for logic that is hard to
  get right; never mock opencode or the face to test the plugin.
- Run long e2e jobs detached and poll; a tool timeout must not kill a run and orphan its universe.

## Writing

- Every file is read later by someone with no memory of the session. No status in artifacts.
- Be concise, prefer code blocks over tables, never write em dashes.
- Conventional commits without a scope: `feat:`, `fix:`, `test:`, `docs:`, `chore:`.
- Never modify this file unless explicitly told.
